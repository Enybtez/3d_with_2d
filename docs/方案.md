# 2D 插画转 3D 再三渲二：黑客松 MVP 方案

日期：2026-09-23。目标设备：一台 NVIDIA DGX Spark。输入范围：单个主体的插画或卡通图。

## 比赛与目标

公开赛事介绍称，本次 DGX Spark 黑客松聚焦 Agent Skills，初赛提交窗口为 2026-09-20 至 09-29，决赛展示为 10-15。报名截止日期写为 09-19；是否仍可参赛、正式评分细则和提交格式必须以主办方通知为准。演示重点应放在「领域 Skill 指导多 Agent，Agent 通过 MCP 工具在本地完成实际制作」。

## 推荐路线

1. 一张 PNG/JPEG 插画上传到本机 Web 页面。
2. 分析 Agent 使用本地 Qwen3-VL 读取图像，按项目 Skill 输出主体描述和可见性判断。
3. 建模 Agent 通过 MCP 调用本地 Hunyuan3D 2.1 API，保存真实 GLB。
4. 风格 Agent 通过 MCP 调用本地 Blender，输出卡通分层着色和轮廓线 PNG。
5. 质检 Agent 使用同一个本地视觉模型对原图与预览作简短比较，保存可追溯的结果。
6. 页面提供原图、预览、GLB 下载、步骤状态与评价。任务记录落盘，断开后可查。

一阶段先实现接口、编排、Skill、MCP 服务和页面，并用本地替身服务验证流程。DGX Spark 上的真实 Hunyuan3D 和 Blender 联调列为实机验收，不把替身生成视为正式效果。

## 选型比较

| 路线 | 优点 | 主要代价 | 结论 |
|---|---|---|---|
| Hunyuan3D 2.1 API + Blender | 上游有明确的本地 HTTP API 和 GLB 输出；工具边界清晰 | ARM64 CUDA 扩展需实机编译验证；模型许可需核对 | MVP 推荐 |
| TRELLIS.2 + Blender | 模型质量潜力高，含材质 | 官方仅声明 A100/H100 已验证；安装多个 CUDA 扩展，对 Spark 风险较高 | 备选 |
| ComfyUI 单体工作流 | 视觉编排直观 | Agent/Skill/MCP 故事较弱，工作流集成更重 | 暂缓 |

DGX Spark 的 128 GB 是 CPU/GPU 统一内存，并不等于所有 CUDA 扩展已经适配 ARM64/GB10。Hunyuan 官方估计形状加纹理约需 29 GB 显存，这只说明内存容量有余量；不能据此保证可运行或速度。默认开纹理以保留插画配色，可在实机压力过大时先验证纯形状链路。

## 阶段划分

| 阶段 | 可验收交付 |
|---|---|
| 第一阶段 | 方案、需求、设计、实施计划；本地 Web/CLI、Skill、MCP、模型/渲染适配器、可运行自动测试、断点状态文档 |
| 第二阶段 | Spark 安装模型权重与 Blender；用至少 3 张自有插画真实生成，记录时延、内存和失败原因并修复 |
| 第三阶段 | 参赛演示视频、项目介绍、评审材料和正式提交核对 |

## 主要风险与选择

- 单图看不到背面，3D 背面由模型推断；演示选择轮廓清楚、背景干净的单主体图。
- Hunyuan3D 2.1 的社区许可有地域和规模条款；下载权重前核对原始许可及比赛作品使用范围。
- Hunyuan 服务、Ollama、Blender 分进程运行，避免 Python/CUDA 依赖互相污染。
- 任务串行执行，避免一台 Spark 上的并发推理争抢统一内存。
- 一阶段不设自动返工循环，质检结果由人判断是否重试，减少不受控的长任务。
